# 字幕窗的尺寸与字号（为什么拖高/拖矮、字号会自己变）

> 起因：用户 2026-09-12 反馈两条 ——
> ① **上下拖动没反应**：拖高拖矮都弹回原来大小（只有左右能缩放）；
> ② **设置 3 行时最顶上会空一行**。
> 顺带落地用户提的"动态字号"：装不下就缩字，长句过去后自动回到基准值。

## 1. 两个毛病的根因是同一个：高度按"最大行数"预留

旧实现的自动高度是
`最多可能几行 × 行高`，其中"最多可能几行" = `每屏条数 × 每条最多换行 × 双语再乘 2`。
默认值（3 条 × 2 行 × 双语）= **12 行**，字号 34pt 时就是 **约 650px 高**，
而实际内容常常只有 4~7 行。

于是：

| 现象 | 旧代码干了什么 |
|---|---|
| 顶上空一行 | 内容不足 12 行时**底部对齐**，少掉的那些行就成了顶上的空白 |
| 上下拖不动 | `_relayout()` 里写的是 `resize(w, max(自动高度, 用户高度))`，自动高度 650px 永远更大 → 用户拖出来的高度被顶回去；而且手动高度只在 `window_height == 0` 时才记录，**存过一次以后再也不更新** |

## 2. 现在的规则

| 场景 | 高度 | 字号 |
|---|---|---|
| 没拖过（`window_height = 0`，默认） | **正好等于当前字幕实际占的行数**（不留空行）。顶部固定、下边缘朝下？——不，窗口锁在屏幕底部，所以是"往下长"变成"往上长" | 基准字号（`font_size`） |
| 拖过上下边缘 / 设置里填了高度 | **完全听你的**，不再被自动高度顶回去 | 内容放得下就用基准；放不下就动态缩小 |

其他细节：

- 拖**上边缘**：窗口锁在屏幕底部，所以是"往上长"，符合字幕直觉；拖下边缘则会被底部锚点拉回来，效果同样是把窗口变高/变矮。
- `auto_font_scale`（拉宽→字号跟着变大）只在**宽度**变化时生效；只拖上下不会改字号。
- 宽度基准用的是"上一次真正生效的宽度"，不是 `config.window_width`——否则小屏上（配置 1200 实际被夹到 760）第一次拖高就会误判成"宽度变了"顺手改掉字号。

## 3. 动态字号（用户要的那条）

- **基准字号** = 设置里的"字号"（`overlay.font_size`）。
- 当前内容在窗口里放不下时，把字号**缩小到刚好放得下**；下限是基准的 **60%**（且不低于 8pt）。再小就不如让长句换行/把最老那行顶走——看不清等于没有。
- **每次重新排版都从基准字号重算**，不做"记住上次缩了多少"。所以内容一少（长句过去了、窗口拉大了），字号下一帧就自动回到你设置的值。
- 关掉开关就完全不缩字：`外观 → 放不下时自动缩小字号`，对应 `overlay.auto_shrink_font`（默认开）。
- 窗口真装不下时（比如你把窗口拖到很矮、又来了很多行），先牺牲**最老**的行——最新的字幕永远在窗口里（否则用户会以为"字幕停了"）。

## 4. 相关旋钮在哪

| 想干什么 | 去哪 |
|---|---|
| 窗口高度（0 = 按内容自动） | 设置 → 外观 → 字幕窗高度；或直接**拖字幕窗上/下边缘** |
| 窗口宽度 / 字号 | 设置 → 外观 → 字幕窗宽度 / 字号；或拖左右边缘 |
| 拉宽时字号跟着变大 | `auto_font_scale`（默认开） |
| 放不下时自动缩小字号 | `auto_shrink_font`（默认开） |
| 每屏几条、每条最多换几行 | 设置 → 外观 → 每屏条数 / 每条最多换行 |

## 5. 相关测试

`tests/test_overlay_layout.py`（9 项，offscreen 平台）覆盖：
自动高度正好等于内容行数、内容变少时高度跟着变小（回归"顶上空一行"）、
拖出来的高度被记住且不被顶回去（回归"上下拖不动"）、只拖上下不改字号、
缩字后所有行都放得下、拉大后字号回到基准、关掉开关就不缩、缩放下限。
