# 向导与「重新配置」（换模型 / 补下载的入口）

> 起因：用户反馈「用了几次之后想**重新跑首次运行向导**来改模型下载，但没有入口」——
> 以前只有 `first_run_done` 为假（第一次运行）时才会自动跑一次向导，
> 之后想换语言包只能手改 `data/config.json`。

## 1. 三个入口

| 入口 | 位置 | 说明 |
|---|---|---|
| 图形界面 | **启动窗口 →「向导…」按钮** | 跑字幕之前用，最直观 |
| 图形界面 | **设置 → 模型 →「重新运行「首次运行向导」…」** | 字幕正在跑时也能用；完成后立刻重建识别/翻译引擎，不用重启 |
| 命令行 | `听显译.exe --wizard` / `启动.bat --wizard` / `main.py --wizard` | 脚本化 / 排障时用 |

三者都调同一个 `run_wizard(config)`，并且都吃**调用方那一份 config 对象**，
所以做完立即生效、不会出现"两份配置各说各话"。

## 2. 重跑必须"以现状为默认值"

这是这次补入口时最容易踩的坑：向导五个页面原本是按**首次运行**设计的，
默认值是"出厂状态"——

| 页面 | 首次运行的默认值 | 直接重跑会怎样 |
|---|---|---|
| ③ 下载模型 · 代理 | 空 | **把用户填好的代理清空** |
| ④ 翻译通道 | 本地大模型 LLM | **把用户的百度/有道/DeepL 通道换成 LLM** |
| ② 档位 | 硬件推荐档 | **把用户调好的延迟档位改回推荐值** |
| ② 语言包 | 推荐组合 | 把用户已经装好的包换成推荐组合（看着像要重下一遍） |

所以 `FirstRunWizard` 多了 `rerun` 概念，**默认自动判断**：
`config.first_run_done` 为真 → `rerun = True`（各页用当前配置预填）；否则按首次运行。
调用方不用记着传参数。

`rerun=True` 时：

- **语言包**：默认勾"**已经完整装在本地**"的那些（`installed_packs()` 扫
  `data/models/`），一个都没装才退回当前档位的推荐组合；
  体积提示会写清"其中 N 个已经装好，会自动跳过"。
- **档位**：取当前 `asr.latency_preset` 反推（`realtime→轻量 / balanced→平衡 /
  accurate→性能`）。初始化时用 `_loading` 挡住"勾档位→重置语言包"的联动，
  只有用户**自己**点档位才会改语言包。
- **代理**：用 `config.proxy` 预填（首次运行时配置里本来就是空的，不会预填出别人的地址）。
- **翻译通道**：用 `config.translate` 预填。向导只提供 LLM / 谷歌网页 / 必应网页 /
  不翻译，**设置里还有 5 家官方 API**——遇到向导表示不了的通道会在下拉框里插一条
  「保持当前：百度翻译 API」，避免"改个模型顺手把通道换了"。
- 标题变成「重新配置向导」，第一页文字也说明"改完点完成；不想改就点稍后再设"。

## 3. 收尾行为

- 点「完成并保存」→ 写入 `data/config.json`；从**设置窗**进来时还会发 `saved`
  信号 → 控制窗立刻 `pipeline.reload()` 重建引擎（约 1~2 秒空档），并回读
  延迟档位/代理/翻译通道到界面上。
- 点「稍后再设」（取消）→ **什么都不改**，也不会触发引擎重建。
- 首次运行（`first_run_done=False`）的行为与以前完全一致。
