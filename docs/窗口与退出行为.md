# 窗口与退出行为（谁有权关掉程序）

> 起因：用户实测反馈 —— **把主控制窗收进托盘后，只关掉设置窗，整个程序就退出了**
> （连音频采集线程一起没了）。本文记录根因、统一策略和现在的行为对照表。

## 1. 症状与根因

根因是 Qt 的默认策略 `QApplication::quitOnLastWindowClosed` = **True**：
"最后一个**参与计数**的可见窗口一关，整个 QApplication 就退出"。
而本程序里"谁参与计数"非常反直觉：

| 窗口 | 窗口类型 | 关掉它算不算"最后一个窗口" |
|---|---|---|
| 悬浮字幕窗 | `Qt.Tool` | ❌ 不算（Qt 不给 Tool 窗口设 `WA_QuitOnClose`） |
| 控制窗（已收进托盘） | 普通窗口，但 `hide()` 了 | ❌ 不可见 → 不算 |
| 设置窗 | 普通窗口 | ✅ 算 |

于是"控制窗在托盘 + 关掉设置窗"在 Qt 眼里就是"最后一个窗口关了" → `app.quit()`。
用户看到的就是"关个设置窗把整个程序关了"。

反过来还有第二个坑：`hide()` **不触发** `closeEvent`。如果只是把主窗口藏起来，
程序会一直挂在后台，而用户既看不见也点不到它。

## 2. 统一策略（`app/ui/lifecycle.py`）

1. **关掉自动退出**：控制窗、选择窗口、向导三处入口在创建窗口前都会调
   `configure_quit_policy(app)`。谁都不许"顺手"退出程序。
2. **只有显式入口才真退出**：控制窗「退出」按钮 / 托盘菜单「退出」/
   主窗口右上角 ✕ → `_quit()` → `quit_app()`。
3. **设置窗一个 owner 一个实例**，关掉再打开是**复用**（重新 `show()`），不是新建：
   旧实例里可能还有正在跑的连通性测试线程（`QThread`），销毁它会
   `QThread: Destroyed while thread is still running`，重则直接崩；
   而且反复开关会堆出一打藏起来的窗口。`saved` 信号只接一次，
   否则点一次「保存设置」会重建两遍识别/翻译引擎。
4. **防重入**：`app.quit()` 之后 Qt 还会挨个关窗、再次触发 `closeEvent`，
   所以 `_quit()` 用 `set_quitting()` 做一次性标记。

## 3. 现在的行为一览

| 操作 | 结果 |
|---|---|
| 控制窗「最小化到托盘」 | 控制窗隐藏、托盘图标保留，**程序继续采集** |
| 关闭设置窗（控制窗在托盘里） | 只关设置窗，程序继续采集 ✅ **修的就是这条** |
| 控制窗 ✕ / 「退出」按钮 / 托盘菜单「退出」 | 退出程序（停采集、收托盘）——老行为不变 |
| 控制窗「显示 / 隐藏字幕」（托盘菜单） | 只切悬浮窗可见性 |
| 选择窗口「开始字幕」 | 子进程接管字幕；选择窗口 1.5 s 自检后**自己关闭** |
| 选择窗口 ✕ | 只退选择窗口（字幕是独立子进程，不受影响） |
| 系统没有托盘 | 「最小化到托盘」按钮禁用；控制窗 ✕ 照样能退出 |

选择窗口为什么要"自检后自己关闭"：它以前是 `hide()`，藏起来就再也点不到
（`hide()` 不触发 `closeEvent`，进程一直挂着），而且它不是 `Qt.Tool`，
再加托盘图标就会和字幕进程的托盘图标打架。现在给它 1.5 秒确认子进程活着
（`pythonw.exe` 会把 traceback 吞掉，不这么做用户什么提示都看不到），
活着就关掉自己，秒退就留在界面上报错并提示看日志。

## 4. ⚠️ 写测试必须知道的 Qt 细节

`QApplication.exec()` 只要被"自动退出"结束过一次，**同一进程里后续的
`exec()` 会立刻返回**（Qt 会留下 pending 的退出标记）。这不是我们的 bug，
但会让测试互相污染，所以 `tests/test_ui_lifecycle.py` 里：

* 验证"Qt 默认策略的坑"的用例**单独开子进程**跑；
* 会把事件循环提前结束的用例（验证"✕ = 退出"）放在**文件最后**。
