# 窗口与退出行为（谁有权关掉程序）

> 起因：用户实测反馈 —— **把主控制窗收进托盘后，只关掉设置窗，整个程序就退出了**
> （连音频采集线程一起没了）。本文记录根因、统一策略和现在的行为对照表。

## 1. 症状与根因

根因是 Qt 的默认策略 `QApplication::quitOnLastWindowClosed` = **True**：
"最后一个**参与计数**的可见窗口一关，整个 QApplication 就退出"。
而本程序里"谁参与计数"非常反直觉：

| 窗口 | 窗口类型 | 关掉它算不算"最后一个窗口" |
|---|---|---|
| 悬浮字幕窗 | `Qt.Tool` | ❌ 不算（Qt 不给 Tool 窗口设 `WA_QuitOnClose`） |
| 控制窗（已收进托盘） | 普通窗口，但 `hide()` 了 | ❌ 不可见 → 不算 |
| 设置窗 | 普通窗口 | ✅ 算 |

于是"控制窗在托盘 + 关掉设置窗"在 Qt 眼里就是"最后一个窗口关了" → `app.quit()`。
用户看到的就是"关个设置窗把整个程序关了"。

反过来还有第二个坑：`hide()` **不触发** `closeEvent`。如果只是把主窗口藏起来，
程序会一直挂在后台，而用户既看不见也点不到它。

## 2. 统一策略（`app/ui/lifecycle.py`）

1. **关掉自动退出**：控制窗、选择窗口、向导三处入口在创建窗口前都会调
   `configure_quit_policy(app)`。谁都不许"顺手"退出程序。
2. **只有显式入口才真退出**：控制窗「退出」按钮 / 托盘菜单「退出」/
   主窗口右上角 ✕ → `_quit()` → `quit_app()`。
3. **设置窗一个 owner 一个实例**，关掉再打开是**复用**（重新 `show()`），不是新建：
   旧实例里可能还有正在跑的连通性测试线程（`QThread`），销毁它会
   `QThread: Destroyed while thread is still running`，重则直接崩；
   而且反复开关会堆出一打藏起来的窗口。`saved` 信号只接一次，
   否则点一次「保存设置」会重建两遍识别/翻译引擎。
4. **防重入**：`app.quit()` 之后 Qt 还会挨个关窗、再次触发 `closeEvent`，
   所以 `_quit()` 用 `set_quitting()` 做一次性标记。

## 3. 现在的行为一览

| 操作 | 结果 |
|---|---|
| 控制窗「最小化到托盘」 | 控制窗隐藏、托盘图标保留，**程序继续采集** |
| 关闭设置窗（控制窗在托盘里） | 只关设置窗，程序继续采集 ✅ **修的就是这条** |
| 控制窗 ✕ / 「退出」按钮 / 托盘菜单「退出」 | 退出程序（停采集、收托盘）——老行为不变 |
| 控制窗「显示 / 隐藏字幕」（托盘菜单） | 只切悬浮窗可见性 |
| 选择窗口「开始字幕」 | 子进程接管字幕；选择窗口 1.5 s 自检后**自己关闭** |
| 选择窗口 ✕ | 只退选择窗口（字幕是独立子进程，不受影响） |
| 系统没有托盘 | 「最小化到托盘」按钮禁用；控制窗 ✕ 照样能退出 |

选择窗口为什么要"自检后自己关闭"：它以前是 `hide()`，藏起来就再也点不到
（`hide()` 不触发 `closeEvent`，进程一直挂着），而且它不是 `Qt.Tool`，
再加托盘图标就会和字幕进程的托盘图标打架。现在给它 1.5 秒确认子进程活着
（`pythonw.exe` 会把 traceback 吞掉，不这么做用户什么提示都看不到），
活着就关掉自己，秒退就留在界面上报错并提示看日志。

## 4. 窗口绝不许比屏幕大（标题栏必须够得着）

用户反馈：**设置页内容一多，窗口变得很长，标题栏被顶到屏幕上方之外，拖都拖不动。**

根因是**最小高度**而不是尺寸：设置窗曾经的 `minimumSizeHint` 实测是 **692×1275**——
因为「识别」那一页是一根长竖列（语言 + 阈值 + 电平表 + 延迟档位 + 五个滑杆 +
模型选择 + 向导入口），它的最小高度 1199px 被 `QTabWidget` 继承成了整窗的最小高度。
Qt 会照这个最小尺寸摆窗口，于是标题栏落在屏幕外。

两条一起修（都在 `app/ui/lifecycle.py`）：

| 手段 | 说明 |
|---|---|
| `scrollable(page)` | 把整个分页塞进 `QScrollArea`（`setWidgetResizable=True`、关横向滚动条）。窗口缩小时内容靠竖直滚动够得着，最小高度直接掉到 ~70px |
| `fit_window_to_screen(window)` | 显示前按屏幕可用区域夹一次：尺寸不超过 **92%**、位置也夹回来，保证标题栏在屏幕内。设置窗在 `showEvent` 里夹（只夹一次，之后不跟用户较劲）；向导在 `run_wizard` 里夹 |

另外**拆了一页**：设置窗从 4 个分页变成 5 个——「模型」（识别模型按语言选择 +
语言包下载入口）从「识别」里拆出来了。拆页和滚动区域是互补的：拆页让常用项不用滚，
滚动区域保证再长也不会撑爆窗口。

窗口右下角还有一个 `QSizeGrip`，让"这个窗口能拖大拖小"一眼可见。
`脚本 preview` 出的图：`data/selftest_audio/settings_tab_model.png`（模型页，
带滚动条与缩放手柄）、`settings_tab_asr.png`（识别页，拆完短了很多）。

## 5. ⚠️ 写测试必须知道的 Qt 细节

`QApplication.exec()` 只要被"自动退出"结束过一次，**同一进程里后续的
`exec()` 会立刻返回**（Qt 会留下 pending 的退出标记）。这不是我们的 bug，
但会让测试互相污染，所以 `tests/test_ui_lifecycle.py` 里：

* 验证"Qt 默认策略的坑"的用例**单独开子进程**跑；
* 会把事件循环提前结束的用例（验证"✕ = 退出"）放在**文件最后**。

## 7. 运行中换音源（为什么以前只能启动时选）

用户问过："为什么只有程序开始的时候才能选监听的模式和监听的程序，进了程序反而调不了？"

**答案：那是历史包袱，不是技术限制。** 三件事叠在一起造成的：

| 现状 | 代码依据 | 当初为什么这么写 |
|---|---|---|
| 必须在启动窗口选 | `launcher._start()` → `_spawn_child(["--run", str(pid)])` | 字幕跑在**独立子进程**里（见下） |
| 目标写死在命令行 | `run_subtitles(pid=…)` 里 `spec` 一次定死 | 子进程只拿到这一个 PID |
| 进程序后调不了 | 控制窗只有显示模式/滚动/穿透/透明度/暂停/设置/退出 | 音源被当成"开工前的一次性决定" |

为什么字幕要单独起一个进程——被一个真坑逼的（`launcher.py` 里有注释）：
在同一个 `QApplication` 里再调 `app.exec()` 会报
``QCoreApplication::exec: The event loop is already running``，
而且 `run_subtitles` 的 ``finally: pipeline.stop()`` 会**立刻执行**，
用户看到的是"点了没反应 / 采集不到音频"；独立进程还顺便隔离崩溃。

### 现在怎么做

控制窗新增 **「换音频来源…」**：

- 列表里有 **浏览器标签页** 与**此刻正在发声的程序**（与启动窗口同口径）；
- 选中后走 `SubtitlePipeline.switch_source()`，本质是
  **停当前采集 → 重建引擎 → 按新音源开工**（与"设置保存后立即生效"共用 `restart()`）；
- 字幕窗全程不关，只有约 1~2 秒的识别空档；
- 切完会**清掉旧字幕**（旧音源的字幕留着会让人误以为是新的）。

同时修掉一个相关的硬伤：**启动时目标没在发声，以前直接退出**（`return 2`），
现在改成"先把窗口开起来、状态栏显示等待"——
`CaptureWorker(follow=True)` 本来就是每 2 秒重试解析目标，
所以「先开字幕窗、再开播放器」现在能自动接上。

测试在 `tests/test_source_switch.py`（19 项）：切换顺序、标签页↔进程互切、
失败上报、选择框的当前项/空列表/枚举失败、控制窗真的接上了 pipeline 且清字幕。
