# 静音阈值与电平表（设置里的那个表从哪来的数据）

> 起因：用户反馈「这里静音阈值这里也画个电平表和阈值线条呗，前面启动给个 ui，
> 这里又不给了」——启动窗口的「电平表」有可视化，设置里的阈值却只有一个数字框。

## 1. 阈值是什么

低于这个电平就当作「没有声音」，不送识别。单位 dBFS（0 = 满幅）。

| 场景 | 实测电平 |
|---|---|
| 目标程序**不播放**（进程回环给的是精确的 0） | −∞（显示 −90，即量程下限） |
| 音量调小后的真实语音（本次实测，见 `docs/P1-实测记录.md`） | **≈ −66 dBFS** |
| 正常音量语音 | −30 ~ −15 dBFS |
| 出厂默认阈值 | **−80 dBFS** |

阈值可以调 −100 ~ −20：越小越灵敏（小声也算有声），越大越严格（能过滤底噪）。

## 2. 现在有三个入口，改的是同一个配置项

| 入口 | 能看到的 | 能改的 |
|---|---|---|
| 启动窗口 →「电平表」按钮（独立浮窗） | 实时表 + 阈值线 | 阈值滑杆 |
| 设置 → 识别 → 静音阈值（数字框） | 实时表 + 阈值线 + 实测参考线 | 阈值数值 |
| 设置 → 识别 → 电平表本身 | 同上 | 只显示 |

三处的值都是 `audio.silence_rms_threshold_db`，所以**打开设置窗时会先回读一次**
（独立电平表窗口可能刚改过），并且数值一动，橙色阈值线立刻跟着挪。

## 3. 设置里的表长什么样

复用独立电平表窗口的同一个控件 `app/ui/meter.py: LevelMeterWidget`（同一套观感）：

- 绿/黄/红 **RMS 主条** + **PEAK 细条** + 白色**峰值保持**竖线
- **橙色虚线 = 当前阈值**（跟着上面的数值实时动）
- **蓝色点线 = 实测参考**（−66 dBFS，"音量调小后的真实语音"），让用户一眼看出
  阈值取在哪比较合适
- 读数行：`RMS x dB / PEAK y dB / HOLD z dB`；标题右侧是状态：
  有声 / 静音（低于阈值）/ ⚠ 削波 / 未采集

参考线是这次给 `LevelMeterWidget` 新加的能力（`set_markers`），每条占一行说明，
控件会自动长高。

## 4. 数据从哪来（为什么启动窗口里是"未采集"）

| 进程 | 数据来源 | 表现 |
|---|---|---|
| 字幕进程（控制窗 → 设置…） | 采集线程**每块已经算好的** `last_rms` / `last_peak` | 实时刷新（100ms） |
| 启动窗口（启动窗口 → 设置…） | 没有采集在跑 | 标题写"未采集"，并提示用「电平表」按钮 |

- 为什么用 `last_rms` / `last_peak` 而不是 `CaptureStats.peak`：后者是**整段采集的
  高水位**，拿它画 PEAK 条会一直顶在最右边（看起来像一直削波）。为此给
  `PipelineStats` 加了 `last_peak`（最近一块的峰值），`peak` 仍保留原义。
- 为什么走标量而不是喂样本：字幕进程只有统计值、没有样本。为此给
  `LevelTracker` 加了 `update_values(rms, peak, dt)`，内部与样本版共用同一段
  平滑/峰值保持代码，**保证两处的观感完全一致**（有测试对拍）。
- 只在设置窗**可见时**才轮询（`showEvent` 起、`hideEvent` 停），不白烧 CPU。
- 读数来源抛异常不影响设置界面（只记 debug 日志）。

## 5. 顺手修的显示问题：量程下限 −70 → −90

原来的显示量程是 −70 ~ 0 dBFS，而默认阈值是 −80：阈值线被 `_x_for_db` 夹在
**左边缘**，用户分不出 −80 和 −70。现在量程改成 −90 ~ 0（与
`app/audio/levels.py: MIN_DB` 一致），刻度也补了一条 −80。独立电平表窗口
看到的是同一套刻度，所以两边一致。
