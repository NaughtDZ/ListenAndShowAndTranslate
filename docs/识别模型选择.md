# 识别模型选择（为什么只让你选"能用的"）

> 用户的话：「既然模型是程序硬编码好的会下载哪些模型，那么哪些模型支持哪些语言，
> 程序应该是知道的，这样不是不会产生用户乱下载模型然后乱用的情况吗？」
> —— 对，所以多了这一层：**谁能识别谁**写在注册表里，界面只让选能用的，
> 运行时再兜一道，手改配置文件也乱不了。

## 1. 事实来源：`app/models/registry.py`

| 模型 id | 类型 | 能识别的语言 | 属于哪个语言包 | 2026-09 本机实测 |
|---|---|---|---|---|
| `zipformer-zh-int8` | 流式 | 中文 | `zh` | 中文 **97.6%**、361ms（默认） |
| `zipformer-zh-en-int8` | 流式 | 中文 / 中英混说 / 英语 | `zh-en` | 中英混说默认 |
| `zipformer-en-int8` | 流式 | 英语 | `en` | 英文 **98.3%**、359ms（默认） |
| `sensevoice-int8` | 分块 | 中 / 英 / 日 / 韩 / 粤 | `ja-ko-yue` | 日语 **94.8% / 87.9%**（默认） |
| `parakeet-ja-int8` | 分块 | 日语 | `ja-parakeet` | 88.1% / 79.7%（候选） |
| `dolphin-base-ctc-int8` | 分块 | 40 种亚洲语言 + 22 种中国方言 | `dolphin` | 日语 83.9% / 63.1%（候选） |
| `omnilingual-300m-ctc-int8` | 分块 | 1600 种语言 | `omnilingual` | 未实测（本机无小语种音频） |
| `fire-red-asr2-ctc-zh_en-int8` | 分块 | 中 / 中英 / 英 | `zh-accurate` | 中文 96.2%（候选） |
| `whisper-turbo-int8` | 分块 | 99 种（`"*"`） | `multilingual` | 保留的兜底；英文 97.8% |
| `whisper-tiny-lid` | **语种识别** | —— 它只判断"在说什么语言"，**不出字幕** | `lid` | —— |
| `silero-vad` | **VAD** | —— 只切分语音段，**不出字幕** | `core` | —— |

> 2026-09 新增了 4 个候选（Parakeet-ja / Dolphin / Omnilingual / FireRedASR2-CTC），并且
> **做了横向实测**：结论是它们在**我们的音频**上没有赢过默认模型（日语 Parakeet 88.1% vs
> SenseVoice 94.8%），所以默认路由保持不变，它们作为「可在设置里切换的候选」保留。
> 完整数据与复现命令见 `docs/P2-ASR实测.md` 末节。

这张表就是 `MODELS`，每个语言包只是它的分组（`PACKS`）。于是：

```python
supports_language("sensevoice-int8", "ja")    # True
supports_language("zipformer-zh-int8", "ja")  # False（中文专用）
supports_language("whisper-turbo-int8", "fr") # True（声明了 "*"）
supports_language("whisper-tiny-lid", "ja")   # False（kind=lid，不是识别模型）
supports_language("silero-vad", "zh")         # False（kind=vad）
```

## 2. 三道闸

**① 界面只列能用的**（设置 → **模型** → 「识别模型（按语言）」）

每个语言一行下拉框（中文 / 中英混说 / 英语 / 日语 / 韩语 / 粤语 / 其它语言兜底），
内容 = `"自动（默认：<实测最好的模型>)"` + `models_for_language(语言)`。
所以语种识别模型、VAD、不支持该语言的模型**根本不会出现在列表里**。
选中项的提示里写着它的语言、体积和实测备注。

**② 引擎类型由注册表决定**

用户选模型时只需要关心"哪个更准/更快"，不用管它是流式还是分块：
`route_kwargs_for(model_id)` 会把 `engine` / `streaming` 一起填好
（流式模型塞进分块引擎会直接加载失败，这种坑不该丢给用户）。

**③ 运行时兜底**（`LanguageRouter._active_route`）

配置文件是可以手改的（也可能被旧版本写坏），所以路由器每次取路由都会检查：
模型不存在 / 不是识别模型 / 不支持这门语言 → **退回默认路由**，并在状态栏与日志里
说明原因，例如：

```
⚠️ zh 配置的模型 whisper-tiny-lid 不能用（不存在 / 不是识别模型 / 不支持该语言），
   已改回默认：zipformer-zh-int8
```

同一门语言只提示一次（结果按语言缓存；改了配置会随 `pipeline.reload()` 重建路由器）。
另外 `LanguageRoute.engine` 本身是 `Literal[...]`，写个不存在的引擎连保存都过不去。

## 3. "选了但没下载"怎么办

下拉框里没装好的模型会带「（未下载）」后缀，选它的那一刻下方就会提示：
"⚠️ 选中的模型还没下载：Whisper large-v3-turbo… 点下面「重新运行「首次运行向导」…」
勾选 `multilingual` 语言包即可下载。" —— 提示里的包名是反查 `pack_for_model()` 得来的，
点一次向导就能补上。装完之后重开设置窗（或向导完成时）标记会自动刷新。

真的没下也不要紧：路由器会按降级链（配置的 `fallback_engine` → Whisper）兜住，
只是会用另一个模型，日志里会写清降级到哪个。
