# 代码审计记录（2026-10）

这一轮是**回头通读全仓代码**找出来的问题，不是新功能。每条都写清"用户会看到什么、
根因在哪、怎么修的、哪个测试守着它"，便于日后有人想"优化回去"时先看看代价。

分三类：**逻辑 bug**、**线程安全**、**性能**。最后附"看过但不改"的清单，
说明那些不是遗漏，是权衡。

---

## 一、逻辑 bug

### 1. DeepSeek 的 400 重试是白做的

- **症状**：接 DeepSeek 官方接口后，若端点拒收关思考参数并返回 400，
  程序"去掉参数重试一次"——但**重试还是 400**，那一句永远翻不出来。
- **根因**：重试时手写了一份 `payload.pop(...)` 清单，新增的 `thinking`
  （DeepSeek 官方字段）没跟上。清单散落在判断逻辑里，加一家服务端就容易漏。
- **修法**：把清单提成模块常量 `_THINK_OFF_KEYS`（唯一真源），重试时按它逐个清。
  `thinking_extras()` 各家分支产出的 key 必须都在清单里。
- **测试**：`test_think_off_keys_cover_every_host`（覆盖 5 家）、
  `test_400_retry_strips_thinking_field`（假 client 校验第二次请求不带 thinking）。

### 2. 停止时最后一句没有译文

- **症状**：点退出/停止后，屏幕最后一行只有原文、没有译文。只在停止时出现，很难复现。
- **根因**：`stop()` 的顺序是「置停止标志 → join 翻译线程 → `router.finish()`」。
  `finish()` 冲出来的最后半句被丢进队列，而翻译线程已经退出了，没人消费。
- **修法**：两处一起改——
  1. `stop()` 改成「停采集 → `finish()` 投队列（翻译线程还活着）→ 关引擎 → join」；
  2. 翻译线程的退出条件加上"队列还有货就继续处理"：
     `while not self._stop.is_set() or not self._queue.empty()`。
- **测试**：`test_translate_loop_drains_queue_after_stop`。

### 3. 识别引擎不关，重建时内存只涨不降

- **症状**：改几次设置（每次保存都会重建引擎）后内存明显上涨。
- **根因**：`stop()` 从来不调用 `LanguageRouter.close()`，`prepare()` 直接
  `self.router = LanguageRouter(...)` 覆盖旧的。旧的 onnx session 要等 GC 才释放，
  模型几百 MB。
- **修法**：`stop()` 里显式 `router.close()` / `hub.close()` 并把引用置 `None`
  （置 None 才不会挡住下一次 `prepare()` 的判断）。
- **测试**：`test_stop_closes_router_and_hub`。

### 4. auto 模式下引擎加载失败会无限重试

- **症状**：没装对应模型时，日志每秒刷几千行、CPU 莫名跑满。
- **根因**：引擎构建失败后 `_engines` 里没有条目，于是**每一帧音频**（10ms 一块）
  都重跑一次完整降级链：构造 6 个引擎对象、6 次 `start()` 抛异常、6 条 WARNING。
  auto 分支更糟：还会每 2 秒重跑一遍 LID 推理。
- **修法**：加 `_failed_languages` 记住"这台机器上装不了"的语言，失败一次就放弃
  （配置变了会重建 router，自然会重试）；auto 分支失败时同时把 `_decided` 置真，
  不再反复判定。
- **测试**：`test_router_does_not_retry_failed_language`。

### 5. 攒批等待时间是个笔误表达式

- **原代码**：`wait_s = max(0.05, self.config.translate.stale_drop_s and 0.35)`
- **问题**：`stale_drop_s` 是"译文回来太晚就丢弃"的阈值，和攒批等待毫无关系。
  `x and 0.35` 只是恰好在 x 非 0 时得到 0.35。看着像有逻辑，其实是个 no-op。
- **修法**：提成模块常量 `BATCH_WAIT_S = 0.35` 并写清为什么是 0.35。

### 6. `os.cpu_count() // 4` 与文档承诺不符

- **问题**：文档写"0 = 自动（**物理核数**的一半）"，代码却是"**逻辑核数**的四分之一"。
  有超线程时两者恰好相等（所以一直没被发现），**没有超线程的 4 核机器只给 1 线程**，
  识别慢得莫名其妙。
- **修法**：用 `psutil.cpu_count(logical=False)` 拿物理核再 `// 2`，拿不到才退回逻辑核估算。

### 7. 代理地址不带 `http://` 会被判成"不可达"

- **症状**：填 `127.0.0.1:2333` 点测试，报"不可达"，用户以为代理坏了。
- **根因**：`urlparse("127.0.0.1:2333")` 把整串当 path，`hostname` 为 `None`，
  于是去连 `("", 0)`。
- **修法**：没有 `://` 时先补 `http://`；端口缺省按 scheme 取 80/443；
  连接失败时用 `try/finally` 关 socket（以前异常路径会漏句柄）。

## 二、线程安全

### 8. 在 QThread 里读写 Qt 控件

- **症状**：点"测试当前翻译通道 / 测试全部通道"偶发崩溃；也可能读到半截字符串。
- **根因**：`_run_test()` 把整个 `self._test_*` 丢进 `QThread`，而这些函数体里
  直接 `self.llm_base.text()`、`self.llm_no_think.isChecked()`，甚至
  `self._fill_models()` 去改 `QComboBox`。Qt 控件不是线程安全的。
- **修法**：
  1. 点按钮的**那一刻**（UI 线程）把要用的值抄成快照 `_ChannelProbe`，后台只用快照；
  2. 测试线程只负责返回 `(报告文本, 模型名列表)`，由 UI 线程的 `_on_test_done`
     去填下拉框。
- **测试**：`test_test_thread_returns_models_instead_of_touching_ui`、
  `test_on_test_done_fills_model_box_on_ui_thread`。

### 9. 行号分配跨线程

- **根因**：`SubtitleState.new_id()` 在**采集线程**被调用（定稿一出就要分配行号），
  却是裸的 `self._next_id += 1`。CPython 靠 GIL 侥幸没出事，但那是实现细节。
- **修法**：加锁；并在类文档里写明"行内容只在 UI 线程改，唯一例外是 new_id"。
- **测试**：`test_new_id_is_thread_safe`（8 线程 × 200 次，不许重号）。

## 三、性能

### 10. 换行是 O(n²)

- **根因**：`wrap_text()` 每加一个字就把**整行**重新量一遍
  （`fm.horizontalAdvance(cur + ch)`）。200 字的字幕 ≈ 2 万次字符度量。
  而它每 200ms（partial 刷新）跑一次，还会被"逐档缩字号"反复触发。
- **修法**：逐字符增量累加宽度（`QFontMetrics.horizontalAdvance` 本来就是字形宽度相加，
  不含 kerning），断行处再用一次整体度量校正 → 总度量量降到 O(n)。
- **测试**：`test_wrap_text_matches_old_implementation`（逐字比对结果一致）、
  `test_wrap_text_is_linear_in_measure_calls`（字符度量总量降 8 倍以上）。

### 11. 缩字号是逐档试

- **根因**：`_fit_font_size()` 从 `base-1` 一档一档往下试，每档都是一次完整 `_wrap_rows`。
  基准 60pt 时最多 40 次全量换行，而 `_relayout()` 每次 partial 都会调用它。
- **修法**：二分查找（~5 次），最后往上补验 3 档，防止禁则/省略号导致的非严格单调
  让它选小了。
- **测试**：`test_fit_font_size_matches_linear_scan`（结果必须和逐档扫一致）。

### 12. 悬浮窗每秒被无条件重绘 2 次

- **根因**：`runner.py` 里有个 500ms 的 `QTimer` 无条件调 `overlay.update()`，
  本意是"累积模式下自动滚动到底"。实际上滚动是 `_relayout()` 里的底部对齐算出来的，
  这个定时器的唯一效果是**只要程序开着就每 500ms 强制重绘**——玩游戏时白烧 GPU，
  无边框全屏下尤其明显。
- **修法**：删掉定时器。重绘本来就是事件驱动的（partial / final / translation 到达时）。

### 13. 绘制循环里重复建字体

- **根因**：`paintEvent()` 每画一行都 `QFontMetrics(self._font(...))` 一次，
  而 `_font()` 内部是 `QFont(self.font())`（复制父字体）。每行两次。
- **修法**：字体与度量提到循环外建一次。

### 14. 拖大文件夹会卡死界面

- **根因**：`studio._add_path()` 用 `sorted(path.rglob("*"))`——先物化整棵目录树再遍历，
  用户不小心拖进整个盘符或几万文件的素材库，UI 线程几十秒无响应。
- **修法**：去掉 `sorted()`（队列顺序本来无所谓），加两道闸：
  最多收 500 个文件、最多看 20000 个目录项，超了就停并在日志里说明。

## 四、界面文案

### 15. 被当成 Markdown 的星号

`QLabel` / `setToolTip` / `QPlainTextEdit` 都是**纯文本**，写 `**加粗**` 只会显示字面的
星号。这轮清掉三处（「模型」页说明、「测试全部通道」的输出、字幕工坊的模型下拉提示）。
`QLabel` 要加粗请用 `<b>`。

### 16. 「不翻译」通道下快捷预设还能点

`_on_provider_changed()` 把 LLM 的输入控件置灰时漏了 `llm_preset`（快捷预设下拉）：
上面全灰、唯独它能点，用户会以为"点这里就能生效"。

## 五、看过但不改

| 位置 | 现象 | 为什么不改 |
| --- | --- | --- |
| `hub.translate()` 部分失败时 `_chars_today` 按整批计 | 字符数会高估 | 成本护栏偏保守是安全的；改成精确统计要区分"哪些真翻成功了"，逻辑更绕 |
| `auto` 模式的语种判定是一次性的 | 直播里换语言不会自动纠正 | 每句都重判会让语言来回跳（同一个主播中日英混说时更糟）；现已把注释改成如实描述，需要换语言请手动指定 |
| `subtitle_overlay` 每次 partial 都全量 `_relayout()` | 内容变一次就重排一次 | 现在单次成本已经降到 O(n) + 二分缩字；再上缓存要维护"布局指纹"，收益不值这个复杂度 |
| 字幕窗 `_reposition()` 在未锁定时不动位置 | 关掉「锁定位置」后不会自动贴底 | 用户取消锁定往往是想自己摆位置，程序自动挪反而烦人 |
| `openai_compat._TRAD_TO_SIMP` 只覆盖几十个字 | 不是完整繁简转换表 | 它只服务"术语校验别误报"，不是给人做转换用；完整表要几百 KB 且会引入误判 |
